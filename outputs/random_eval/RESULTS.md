# Burst prediction on random workloads — leak-free, real xv6, with a control

Generated by `experiments/burst_random_eval.py` (+ `experiments/workload_gen.py`)
on the **real xv6 kernel** (deterministic `-icount`), prompt leak closed
(`description`/`id`/`label` stripped). Run: `--n-signal 8 --n-control 4 --procs 6
--algos SRTF,SJF`. Positive % = lower avg_waiting than blind EMA cold-start.

## Result

| regime | n | mean ordering acc (ema / heur / llm) | SRTF llm vs EMA | SJF llm vs EMA |
|---|---|---|---|---|
| **signal**  | 8 | 0.50 / 0.695 / 0.683 | **+8.6%** ±17.9 | **+8.5%** ±16.5 |
| **control** | 4 | 0.50 / 0.391 / 0.367 | **−7.5%** ±24.3 | **−18.0%** ±24.4 |

(heuristic vs EMA: signal +8.6%/+8.4%, control −6.1%/−12.3%.)

## What this DOES show (honest positives)
1. **The methodology is sound — the negative control passes.** When burst is
   independent of the visible features (control), the LLM does **not** win; it
   ordering-scores at chance (0.37) and actually *hurts* avg_waiting (−7.5%/−18%),
   exactly like over-differentiating noise. So a "win" on the signal set cannot be
   a leak — there is nothing left to leak. This is the key credibility result.
2. **Feature-based burst prediction improves SJF/SRTF over blind EMA** on
   workloads that have real, leak-free signal: ~**+8.5%** lower average waiting,
   directionally consistent across SRTF and SJF, with ordering accuracy rising
   0.50 → ~0.69.

## What this does NOT show (honest limits)
3. **Not statistically conclusive at n=8** — the 95% CI (±18) overlaps zero. A
   larger workload count is needed to call the signal-set win significant.
4. **The LLM does NOT beat a simple heuristic here** (llm +8.6% ≈ heuristic
   +8.6%; ordering 0.68 ≈ 0.70). The value measured is "*predicting burst from
   visible features beats a blind constant*," not "*the LLM is better than a
   hand rule*." Our generator's signal is essentially one graded feature
   (`io_count`), which the binary heuristic already captures; it does not exercise
   the multi-feature reasoning where an LLM could pull ahead.
5. **Prediction can hurt when there is no signal** (control, −8 to −18%): acting
   on a non-existent burst structure reorders equal jobs wrongly. This motivates a
   low-variance → fall-back-to-EMA guard (same lesson as the old `short_jobs`
   case), now confirmed on the real kernel.

## Follow-up — multi-feature signal vs a FAIR strong heuristic (scout, n=6/4, SRTF)

To test whether the LLM's *reasoning* beats a good rule (not just blind EMA), a
second generator (`--signal multi`) splits the signal across TWO noisy features
(`io_count` AND `priority`, ~40% noise each) so no single feature is reliable, and
a **fair multi-feature graded heuristic** (`predict_strong_heuristic`, fuses both)
is the competitor. Result:

| regime | EMA | weak heur | **strong heur** | **LLM** |
|---|---|---|---|---|
| signal ordering acc | 0.50 | 0.587 | **0.736** | **0.505** |
| signal SRTF vs EMA  | — | +12.3% | **+19.4%** | **+1.4%** |
| control ordering acc | 0.50 | 0.391 | 0.217 | 0.367 |
| control SRTF vs EMA | — | −6.1% | −22.2% | −7.5% |

**The LLM FAILED on the multi-feature signal** — ordering 0.505 (≈ chance), barely
above blind EMA (+1.4%), and WORSE than even the weak single-feature heuristic.
The fair strong heuristic dominated (0.736, +19.4%). Inspecting the predictions,
the LLM does not consistently fuse two noisy numeric cues: it misses cases where
both features clearly agree and weights `priority` inconsistently. A rule tuned to
the generator's directions (which IS the generator's own mapping) trivially beats
it. On the CONTROL set no strategy wins, and the most *confident* predictor (the
strong heuristic) hurts MOST (−22%) — confidence on noise is costly.

## Bottom line (both experiments)
On the real xv6 kernel, leak-free and with a negative control:
1. **A burst prior helps SJF/SRTF only when real visible signal exists** (single
   feature: +8.5% vs blind EMA; control: no help / hurts). The methodology is
   sound — the negative control never lets a spurious win through.
2. **The LLM does NOT beat conventional prediction.** With a single easy feature
   it merely ties a trivial heuristic; with a two-feature signal it **fails**
   (ordering ≈ chance, +1.4%) while a fair fused heuristic wins big (+19.4%). The
   LLM cannot reliably fuse noisy NUMERIC features the way a rule tuned to the
   data can — empirically confirming that on tabular numeric inputs a hand rule
   (≈ the data-generating mapping) is the ceiling, not the LLM.
3. **Confidence on no-signal is costly:** on the control set the most confident
   predictor (strong heuristic) hurt most (−22%), motivating a low-variance →
   fall-back-to-EMA guard.

This is an honest NEGATIVE result for "the LLM is a better burst predictor",
consistent with the project's other measured negatives (LLM-picks-best, ODA). The
LLM's plausible value is on inputs a rule can't easily encode (semantic/textual),
which numeric burst features are not. We did not scale N further because the scout
gap (LLM 0.505 vs strong-heur 0.736) is decisive, not marginal.
