# dashboard_live — Final Live Data Dashboard

This is the **final project dashboard** that reads real generated trace/metrics data.

It does **not** use static fixture data as the primary source.
It fetches data from `public/live-data/` at runtime.

## Purpose

- Visualize real execution data from the scheduler simulator or xv6
- Replay mode: scrub through trace events with a tick slider
- Live mode: poll `manifest.json` every 1 second and auto-update

## Data source

`public/live-data/` — generated by `scripts/run_live_dashboard_pipeline.py`.

Files loaded at runtime:
- `manifest.json` — version + metadata, polled in Live mode
- `recommendation.json` — LLM recommendation
- `guard_decision.json` — Algorithm Guard decision
- `workload_summary.json` — workload characteristics
- `metrics.json` — scheduling metrics + comparison
- `trace_rr.jsonl`, `trace_fcfs.jsonl`, `trace_priority.jsonl`, `trace_mlfq.jsonl`, `trace_sjf.jsonl`, `trace_srtf.jsonl`

## Run

### 1. Generate live data first

```bash
python3 scripts/run_live_dashboard_pipeline.py
```

### 2. Start dashboard

```bash
cd dashboard_live
npm install
npm run dev    # http://localhost:5174
```

### 3. Build

```bash
npm run build
```

## Limitations

- Current pipeline uses host-side simulator (`tools/scheduler_simulator.py`) as the execution backend.
- xv6/QEMU raw log integration: use `--mode xv6-log --xv6-log <path>` once `tools/trace_parser.py` supports the raw console log format.
- Live mode uses polling (1s), not websocket.
- `fallbackData.js` is used only when all live-data files fail to load.
